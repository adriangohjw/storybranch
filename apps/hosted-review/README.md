# Hosted visual review

TanStack Start app for team review of CI visual runs. Local `storybranch test` / `review` is unchanged when no project token is set.

## Prerequisites

- [Docker](https://docs.docker.com/get-docker/) (Compose v2: `docker compose`)
- [Bun](https://bun.com) — only for **dev mode** (Vite on the host)
- macOS or Linux (setup script is bash). On Windows, use WSL2 for Docker and the script.

## Quick start

From the **repo root**:

```bash
bun run --cwd apps/hosted-review setup
docker compose -f apps/hosted-review/docker-compose.yml up --build
```

Open [http://127.0.0.1:3000/login](http://127.0.0.1:3000/login). Sign in with the admin email from `.env` (`STORYBRANCH_ADMIN_EMAIL`).

Setup copies [`.env.example`](./.env.example) → `.env` if needed and replaces the placeholder `BETTER_AUTH_SECRET`. Flags: `./apps/hosted-review/scripts/setup.sh --email you@company.com`.

## Environment variables

| Variable | Required | Purpose |
|----------|----------|---------|
| `BETTER_AUTH_SECRET` | yes | Session signing; **≥ 32 characters**. Generated by `setup` if still the example value. |
| `DATABASE_URL` | yes | Postgres URL. Compose: `postgres://storybranch:storybranch@postgres:5432/storybranch`. Host dev: `@127.0.0.1:5432`. |
| `STORYBRANCH_APP_URL` | yes | Public URL of this app (no trailing slash), e.g. `http://127.0.0.1:3000`. |
| `STORYBRANCH_ADMIN_EMAIL` | no | Bootstraps an **admin** invite on first DB init. Use this address on the login screen. |
| `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` | yes | Object storage for baselines and run PNGs. |
| `S3_ENDPOINT` | no | Custom S3 API (Floci locally: `http://127.0.0.1:4566`). Omit for AWS. |
| `S3_REGION` | no | Default `us-east-1`. |
| `S3_FORCE_PATH_STYLE` | no | `true` for Floci and most self-hosted S3. |
| `RESEND_API_KEY`, `RESEND_FROM` | prod | Resend sender for magic links. |
| `STORYBRANCH_DANGEROUS_EMAIL_LOG` | dev | Set to `1` to **log** magic links instead of sending mail. Default in `.env.example`. **Unset in production.** |

Validation runs at app boot ([`src/lib/env.ts`](./src/lib/env.ts)): without `STORYBRANCH_DANGEROUS_EMAIL_LOG=1`, Resend vars are required.

## Docker Compose stack

| Service | Role |
|---------|------|
| `postgres` | App database |
| `floci` | Local S3-compatible storage ([Floci](https://floci.io), port `4566`) |
| `s3-init` | Creates the `storybranch` bucket once |
| `app` | Production-style image on port `3000` |

Production: run the app image (or `bun run build` + `start`) against your own Postgres and bucket (AWS S3, R2, Garage, etc.) using the same `S3_*` names.

## Dev mode (hot reload)

Postgres + Floci in Docker; Vite on the host:

```bash
docker compose -f apps/hosted-review/docker-compose.yml up postgres floci s3-init
set -a && source apps/hosted-review/.env && set +a
bun run --cwd apps/hosted-review dev
```

## First login and mail

1. Ensure `STORYBRANCH_ADMIN_EMAIL` is your address (setup script or `.env`).
2. With `STORYBRANCH_DANGEROUS_EMAIL_LOG=1`, request a magic link on `/login` and read the URL from **app or compose logs** (not email).
3. For real mail: remove `STORYBRANCH_DANGEROUS_EMAIL_LOG`, set `RESEND_API_KEY` and `RESEND_FROM`, restart the app.

## Project + CI token

1. Sign in as admin → **Projects** → create a project.
2. Open the project → **Create project token** → copy the token (shown once).
3. In GitHub (or your CI), set secret `STORYBRANCH_PROJECT_TOKEN` and env `STORYBRANCH_API_URL` to your app URL (no trailing slash).

Workflow template: [`examples/github-actions/hosted-visual-review.yml`](../../examples/github-actions/hosted-visual-review.yml).

```bash
storybranch test --build --exit-once \
  --project-token "$STORYBRANCH_PROJECT_TOKEN" \
  --api-url "https://review.example"
```

With `GITHUB_TOKEN` and a PR number (`STORYBRANCH_PR_NUMBER` or `refs/pull/N/merge`), CI also posts commit status `storybranch / visual` and one updatable PR comment.
