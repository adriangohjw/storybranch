# Hosted visual review

TanStack Start app for team review of CI visual runs. Local `storybranch test` / `review` is unchanged when no project token is set.

## Prerequisites

- [Docker](https://docs.docker.com/get-docker/) (Compose v2: `docker compose`)
- [Bun](https://bun.com) — runs the TanStack Start app on the host
- macOS or Linux (setup script is bash). On Windows, use WSL2 for Docker and the script.

## Quick start

From the **repo root**:

```bash
bun run --cwd apps/hosted-review setup
docker compose -f apps/hosted-review/docker-compose.yml up -d
bun run --cwd apps/hosted-review dev
```

`dev` applies the Prisma migrations, then starts Vite. Open [http://127.0.0.1:3000/login](http://127.0.0.1:3000/login). Sign in with the admin email from `.env` (`STORYBRANCH_ADMIN_EMAIL`). Bun loads that file.

Setup copies [`.env.example`](./.env.example) → `.env` if needed and replaces the placeholder `BETTER_AUTH_SECRET`. Flags: `./apps/hosted-review/scripts/setup.sh --email you@company.com`.

## Environment variables

| Variable | Required | Purpose |
| --- | --- | --- |
| `BETTER_AUTH_SECRET` | yes | Session signing; **≥ 32 characters**. Generated by `setup` if still the example value. |
| `DATABASE_URL` | yes | Postgres URL. Host app: `postgres://storybranch:storybranch@127.0.0.1:5432/storybranch` (already in `.env.example`). |
| `STORYBRANCH_APP_URL` | yes | Public URL of this app (no trailing slash), e.g. `http://127.0.0.1:3000`. |
| `STORYBRANCH_ADMIN_EMAIL` | no | Bootstraps an **admin** invite on first DB init. Use this address on the login screen. |
| `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` | yes | Object storage for baselines and run PNGs. |
| `S3_ENDPOINT` | no | Custom S3 API (Floci locally: `http://127.0.0.1:4566`). Omit for AWS. |
| `S3_REGION` | no | Default `us-east-1`. |
| `S3_FORCE_PATH_STYLE` | no | `true` for Floci and most self-hosted S3. |
| `RESEND_API_KEY`, `RESEND_FROM` | prod | Resend sender for magic links. |
| `STORYBRANCH_DANGEROUS_EMAIL_LOG` | dev | Set to `1` to **log** magic links instead of sending mail. Default in `.env.example`. **Unset in production.** |
| `STORYBRANCH_OBJECT_STORAGE` | CF | Set to `r2` in Worker `[vars]` when using the `OBJECTS` R2 binding (no `S3_*` keys). |
| `STORYBRANCH_DATABASE` | CF | Set to `hyperdrive` in Worker `[vars]` when using the `HYPERDRIVE` binding (no `DATABASE_URL`). |

Validation runs at app boot ([`src/lib/env.ts`](./src/lib/env.ts)): without `STORYBRANCH_DANGEROUS_EMAIL_LOG=1`, Resend vars are required.

## Docker Compose stack

| Service | Role |
| --- | --- |
| `postgres` | App database |
| `floci` | Local S3-compatible storage ([Floci](https://floci.io), port `4566`) |
| `s3-init` | Creates the `storybranch` bucket once |
| `app` | Optional image on port `3000` (`docker compose --profile app up -d --build`) |

`docker compose up -d` starts Postgres and Floci in the background. The app runs with `bun run dev` and reads `apps/hosted-review/.env` (`127.0.0.1` ports). Production: the image, or `bun run build` + `start`, against your own Postgres and bucket (AWS S3, R2, Garage, etc.) using the same `S3_*` names.

## First login and mail

1. Ensure `STORYBRANCH_ADMIN_EMAIL` is your address (setup script or `.env`).
2. With `STORYBRANCH_DANGEROUS_EMAIL_LOG=1`, request a magic link on `/login` and read the URL from the dev server logs (not email).
3. For real mail: remove `STORYBRANCH_DANGEROUS_EMAIL_LOG`, set `RESEND_API_KEY` and `RESEND_FROM`, restart the app.

## Project + CI token

1. Sign in as admin → **Projects** → create a project.
2. Open the project → **Create project token** → copy the token (shown once).
3. In GitHub (or your CI), set secret `STORYBRANCH_PROJECT_TOKEN` and env `STORYBRANCH_API_URL` to your app URL (no trailing slash).

Workflow template: [`examples/github-actions/hosted-visual-review.yml`](../../examples/github-actions/hosted-visual-review.yml).

```bash
storybranch test --build --exit-once \
  --project-token "$STORYBRANCH_PROJECT_TOKEN" \
  --api-url "https://review.example"
```

With `GITHUB_TOKEN` and a PR number (`STORYBRANCH_PR_NUMBER` or `refs/pull/N/merge`), CI also posts commit status `storybranch / visual` and one updatable PR comment.

## Scripts

| Command                   | Action                                       |
| ------------------------- | -------------------------------------------- |
| `bun run setup`           | Run [`scripts/setup.sh`](./scripts/setup.sh) |
| `bun run dev`             | Apply migrations, then the Vite dev server   |
| `bun run db:migrate`      | Apply Prisma migrations                      |
| `bun run db:reset`        | Drop DB, reapply migrations (uses `.env`)    |
| `bun run db:generate`     | Regenerate Kysely types from `schema.prisma` |
| `bun run build` / `start` | Production build (Node)                      |
| `bun run build:cloudflare` | Worker build (Nitro `cloudflare-module`)    |
| `bun run deploy:cloudflare` | Build + `wrangler deploy` (see below)      |

## Deploy on Cloudflare

Hosted review can run on **Cloudflare Workers** with **R2** for PNG storage and **Hyperdrive** for Postgres (same Prisma schema and migrations as Docker Compose — run migrations against your origin database, not inside the Worker).

### 1. Cloudflare account and Wrangler

1. Create or open a [Cloudflare account](https://dash.cloudflare.com/).
2. Install Wrangler (included as a dev dependency): `bun install` from the repo root.
3. Log in: `bunx wrangler login` (from any directory).

### 2. R2 bucket

1. Dashboard → **R2** → **Create bucket** (e.g. `storybranch-review`).
2. Or CLI: `bunx wrangler r2 bucket create storybranch-review`
3. In [`wrangler.toml`](./wrangler.toml), set `bucket_name` under `[[r2_buckets]]` to match. The Worker binding name is **`OBJECTS`** (do not rename without code changes).

### 3. Postgres + Hyperdrive

1. Provision Postgres (e.g. [Neon](https://neon.tech), RDS, or the Compose Postgres URL for experiments only).
2. Apply migrations from your machine (uses `DATABASE_URL` in `.env` pointing at the **origin** DB):

   ```bash
   bun run --cwd apps/hosted-review db:migrate
   ```

3. Dashboard → **Workers & Pages** → **Hyperdrive** → **Create configuration** → connect to that Postgres.
4. Copy the Hyperdrive **configuration id** into `wrangler.toml` (`[[hyperdrive]]` → `id = "..."`). Binding name is **`HYPERDRIVE`**.

### 4. Worker vars and secrets

Edit [`wrangler.toml`](./wrangler.toml):

- Set `[vars]` **`STORYBRANCH_APP_URL`** to your public URL (no trailing slash), e.g. `https://storybranch-hosted-review.<subdomain>.workers.dev` after the first deploy, or your custom domain.

Set secrets (never commit these):

```bash
cd apps/hosted-review
bunx wrangler secret put BETTER_AUTH_SECRET
bunx wrangler secret put RESEND_API_KEY   # omit if using email log in dev only
bunx wrangler secret put RESEND_FROM
# Optional: STORYBRANCH_ADMIN_EMAIL as a secret or [vars] entry
```

For local-style magic links in a staging Worker, you can set `[vars]` `STORYBRANCH_DANGEROUS_EMAIL_LOG = "1"` and skip Resend secrets (not for production).

`[vars]` already includes:

| Var | Purpose |
| --- | --- |
| `STORYBRANCH_OBJECT_STORAGE=r2` | Use R2 binding instead of `S3_*` credentials |
| `STORYBRANCH_DATABASE=hyperdrive` | Use Hyperdrive binding instead of `DATABASE_URL` |

### 5. Build and deploy

From `apps/hosted-review`:

```bash
bun run deploy:cloudflare
```

Equivalent manual steps:

```bash
bun run build:cloudflare
bunx wrangler deploy --config .output/server/wrangler.json
```

Nitro merges this app’s [`wrangler.toml`](./wrangler.toml) into the generated `.output/server/wrangler.json`. The Worker serves the app; static assets use the `ASSETS` binding.

### 6. Custom domain (optional)

Dashboard → **Workers & Pages** → your worker → **Settings** → **Domains** → add a route or custom domain. Update `STORYBRANCH_APP_URL` and redeploy.

### 7. CI / GitHub Actions

Point `STORYBRANCH_API_URL` at the Worker URL (or custom domain). Use the same project token flow as self-hosted.

**Docker Compose** (`docker compose -f apps/hosted-review/docker-compose.yml`) remains the local and self-hosted path; nothing in this section replaces it.
